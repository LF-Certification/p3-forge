# Changelog

## [Unreleased]

### 🚀 Features

- `context current`, `context use` and `version` print JSON or YAML with `-o json|yaml` and work with `--jq`
- Plugin manifest records the SDK version (`sdk_version`) the plugin was built with
- SDK plugins accept the forwarded `--context`, `--jq`, `--yes` and `--insecure-storage` flags; `LFED_YES` turns on every `--yes` flag of the plugin
- `plugin install` and `plugin upgrade` verify a Sigstore (cosign) signature attached to the plugin's OCI index before they pull or run it; `--allow-unsigned` skips the check, and `LFED_PLUGIN_SIGNER_IDENTITY` with `LFED_PLUGIN_SIGNER_ISSUER` set the signer for registries other than the default
- `plugin install` accepts digest pins (`<name>@sha256:<hex>`, `<registry>/<repository>@sha256:<hex>`) and records the resolved index digest and the pin in `lfed-plugin.json`
- `plugin upgrade` skips plugins pinned to a version or digest ("pinned to …; reinstall to change")
- `LFED_PLUGIN_DIR` is a supported override of the plugin directory

### 🐛 Bug Fixes

- Usage errors (unknown flag, unknown subcommand of `context`, `auth` or `plugin`, bad argument count) exit 2 instead of 1 or 0
- SIGINT and SIGTERM cancel the running command so cleanup runs; `lfed` and SDK plugins exit 130
- `--jq` reports output write errors
- Only the long forms of the global flags apply after the plugin name; `-c` and `-o` there belong to the plugin
- `auth logout` removes the credentials from the system keychain and from the `--insecure-storage` file, with or without the flag
- `auth login` with the other storage backend removes the credentials of the previous login
- A lock file `lock-<context>` in the state directory makes concurrent `lfed` processes refresh an access token once
- Credential, login state and config files are replaced atomically with mode 0600; their directories get mode 0700
- Requests to Auth0 time out after 30 seconds
- `auth token` uses the plain-file backend when `LFED_INSECURE_STORAGE` is set, so plugins of an `lfed --insecure-storage` run get a token
- The SDK rejects a plain-http `LFED_API_BASE_URL` unless the host is loopback
- SDK `auth.Token` ignores an exported `LFED_TOKEN` and always gets the token from `lfed auth token`
- `plugin remove` and plugin dispatch reject names that are not plugin names (such as `../..`) with "unknown command" and exit 2; nothing outside the plugin directory is removed
- `plugin remove` removes a broken install (a directory without a manifest)
- `GITHUB_TOKEN`, `GH_TOKEN` and `gh auth token` are sent to ghcr.io only; other registries use only the Docker credential store
- A failed plugin install or upgrade keeps the previous install; the old directory is removed only after the new one is in place
- Plugin downloads refuse an index or platform manifest above 4 MiB, a layer above 512 MiB (compressed or expanded), a layer with more than 64 tar entries or with absolute or `..` entry names, and a platform manifest with another `artifactType`
- Registry requests time out on connect (10 s), TLS handshake (10 s) and response headers (30 s)
- `__metadata` at install time runs with a minimal environment and a 30-second timeout
- Plugins no longer get `LFED_TOKEN` or an appended `--yes`; they get `LFED_YES` and `LFED_INSECURE_STORAGE` (empty when the flag is not set)
- A plugin killed by signal N exits 128+N; `lfed` waits for a running plugin and never kills it, relays SIGTERM to it, and leaves SIGINT to the terminal, which delivers it to both
- Running a plugin whose manifest has another `schema_version` asks for a reinstall
- Signature discovery reads at most 4 referrer pages and 16 signature referrers per index; a longer list is an error
- SDK plugins end a command that does not return within `plugin.CancelGrace` (3 s) after SIGINT or SIGTERM with exit 130, so a blocked prompt does not hang
